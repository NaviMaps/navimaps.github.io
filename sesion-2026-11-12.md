### v7: Tus puntos y "Cómo llegar"
Pedido: que el buscador encuentre los puntos guardados y que al tocar uno aparezca un menú para llegar, como en Google Maps.
- **Tocar un punto guardado** (en el mapa o en el buscador) abre una tarjeta con el nombre, la distancia y **Cómo llegar**.
- **Cómo llegar** marca el destino y **calcula sola la ruta por agua**. Si no sabe dónde estás, primero busca tu posición.
- Cuando termina, el mapa **encuadra toda la ruta** por encima del panel de abajo, que dice "Hacia [nombre]".
- Los ➤ de los resultados y de la lista de puntos hacen lo mismo.

### v8: Buscador unificado
Pedido: que con el buscador vacío aparezca primero el historial, y que buscar el nombre de un punto guardado muestre ese pin (antes se quedaba solo en los cauces).
- **Con el buscador vacío:** primero **Recientes** (🕘) y después las sugerencias.
- **Al buscar** se juntan en una sola lista tus puntos (📍, siempre arriba), los cauces (de `cauces.json`, al instante) y los lugares (del servidor, llegan después con "buscando más…").
- **Si coincide un punto guardado**, el mapa va directo a su pin y abre su tarjeta.

### v9: Arreglo del buscador trabado
Problema: después de encontrar algo, el buscador quedaba en "Buscando…" y no mostraba las sugerencias por un buen rato.
- **Causa:** seguía esperando al servidor de lugares de OpenStreetMap (puede tardar decenas de segundos), y limpiar el buscador no cortaba esa espera.
- **Arreglo:** limpiar (✕) o escribir de nuevo corta la búsqueda anterior. Si ya hay resultados propios o de cauces, al servidor se le dan como mucho 8 segundos.

### v11: Lugares en el mapa
Pregunta: ¿se pueden tener mapeadas las estaciones de servicio y los puntos de interés?
- Opciones que vimos:
  - **Archivo propio `lugares.json`** (elegida): igual que `cauces.json`, se baja una vez y funciona sin señal.
  - Pedirlos al servidor al mover el mapa: lento, inestable y no anda sin señal.
  - Los íconos del mapa base: son parte de la imagen, no se pueden tocar ni buscar.
- **Qué hace la app con el archivo:**
  - Íconos desde zoom 13 (⛽ 🍴 ☕ ⚓ 🛒 🏨 ➕) y nombres desde zoom 16.
  - Al tocar un ícono, tarjeta con tipo (por ejemplo "Combustible náutico"), distancia, **Cómo llegar** y ☆ para guardarlo como punto propio.
  - El buscador, por nombre o por categoría ("combustible", "restaurantes"…), sale todo del celular: al instante y sin señal.
  - Interruptor "Lugares" en ☰ › Capas; cantidad y fecha en Ajustes › Lugares guardados.
  - Sin el archivo, la app sigue buscando en el servidor como antes.
- **Script nuevo `descargar-lugares.ps1`:** baja del rectángulo del Delta las estaciones de servicio (incluidas las náuticas), restaurantes, bares y cafés, marinas, muelles con nombre, guarderías, proveedurías, alojamiento y salud. Arma un `lugares.json` liviano.

## 4. Lo que queda por hacer

### Correr el script de lugares (en la computadora con Windows)
1. **Abrir PowerShell dentro de la carpeta del proyecto:**
   - Forma A: en el Explorador de archivos (Windows + E), entrar a `navimaps.github.io`, hacer clic en un espacio vacío de la barra de dirección, escribir `powershell` y apretar Enter.
   - Forma B: menú Inicio › Windows PowerShell, y después `cd $HOME\navimaps.github.io`.
   - La línea tiene que terminar en `navimaps.github.io>`.
2. **Traer lo último:**
   ```
   git checkout test
   git pull
   ```
3. **Correr el script:**
   ```
   powershell -ExecutionPolicy Bypass -File .\descargar-lugares.ps1
   ```
   Al final tiene que decir en verde `Listo: ...\lugares.json (N lugares, X KB)`.
4. **Subir el archivo:**
   ```
   git add lugares.json
   git commit -m "Lugares del Delta"
   git push
   ```
   La `VERSION` ya está en v11; no hace falta cambiarla esta vez.
5. Si algo da error, copiar lo que muestra la consola y pasárselo a Claude.

### Pasar `test` a `main`
Cuando todo esté aprobado en el iPhone (o en el agua):
```
git checkout main
git merge test
git push
git checkout test
```
